# 데이터 계약

영구 데이터 구조를 만들거나 바꾸기 전에 다음 질문에 답한다.

| 질문 | 필요한 이유 |
| --- | --- |
| 어떤 업무 대상을 저장하는가? | 저장 단위와 각 기록의 의미를 명확히 한다. |
| 핵심 흐름에 꼭 필요한 필드는 무엇인가? | 불필요한 데이터 수집을 막는다. |
| 누가 기록을 생성할 수 있는가? | 쓰기 정책을 정한다. |
| 누가 읽거나 수정할 수 있는가? | 공개 사용자와 운영자의 접근 범위를 정한다. |
| 쓰기 성공을 무엇으로 확인하는가? | 앱에서 검증할 결과를 정한다. |
| 절대 저장하거나 노출하지 않을 정보는 무엇인가? | 개인정보와 기밀을 보호한다. |

확정된 흐름을 지원하는 가장 단순한 데이터 구조를 사용한다. 필수 필드, 시각 정보와 안정적인 식별자를 명시하고, 해당 흐름을 허용하는 범위 안에서 가장 좁은 접근 정책을 적용한다.
