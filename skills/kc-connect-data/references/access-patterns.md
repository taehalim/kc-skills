# 프로젝트에 안전한 접근 방식

현재 사용자의 역할, 데이터 민감도와 운영 방식을 기준으로 가장 단순하면서 안전한 패턴을 선택한다.

## 정적·로컬 데이터

- 준비된 가상 정보를 검색·필터링하거나 브라우저 안에서만 처리할 때 사용한다.
- 실제 개인정보나 회사 자료를 코드 또는 브라우저 저장소에 넣지 않는다.

## 공개 입력과 제한된 운영 조회

- 누구나 제출할 수 있어도 전체 기록의 조회·수정은 인증된 운영자로 제한한다.
- 공개 입력 경계에서 값을 검증하고 운영 요청은 호출자의 신원과 권한을 확인한다.

## 로그인 사용자별 데이터

- 각 사용자가 자신의 기록만 다루어야 하면 사용자 식별자와 소유권 정책을 연결한다.
- 로그인하지 않은 사용자의 허용 행동과 권한 거부 결과를 명시한다.

## 공개 읽기와 제한된 쓰기

- 공개 카탈로그처럼 읽기는 허용하되 생성·수정·삭제는 인증된 운영자로 제한한다.
- 버튼을 숨기거나 서버 함수를 거치는 것만으로 권한을 보호했다고 판단하지 않는다.

데이터베이스가 없어도 핵심 가치가 성립하면 영구 저장을 추가하지 않는다. 사용하는 공급자가 행 단위 정책이나 동등한 접근 제어를 제공하면 가장 좁은 권한으로 구성하고 중요한 거부 동작을 확인한다.
