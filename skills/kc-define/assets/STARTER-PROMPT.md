# kc-define 시작 프롬프트

아이디어 문서, 메모, 업무 자료 또는 현재 대화 맥락을 먼저 제공한 뒤 사용한다.

```text
내가 제공한 아이디어·업무 맥락·자료를 바탕으로 만들 제품을 구체화해줘.

내 입력 상태에 맞춰 진행해줘.
- 아이디어가 부족하면 내가 하는 업무와 반복되는 불편에서 문제 후보를 찾도록 도와줘.
- 일부 맥락만 있으면 구현 방향을 바꾸는 내용만 질문해줘.
- 아이디어가 명확하면 사용자·업무 환경·역할별 과업·IA·정보 우선순위·상태 가시성의 누락을 먼저 점검해줘.

질문은 한 번에 최대 세 개만 하고, 내가 이미 말한 내용은 다시 묻지 마.
UX 전문 용어 대신 실제 업무 장면과 행동을 기준으로 질문해줘.
내가 답하지 않은 내용은 사실처럼 확정하지 말고 가정 또는 미결정 사항으로 표시해줘.

결정이 끝나면 다음 내용을 이 프로젝트의 PRD.md로 정리해줘.
- 주요 사용자와 사용 환경
- 현재 문제와 핵심 사용자 과업
- 역할별 화면이나 정보 우선순위의 차이
- IA와 핵심 화면 흐름
- 입력·오류·빈 상태·완료 상태
- 필수 범위와 제외 범위
- 수용 시나리오와 남은 가정

코드는 아직 구현하지 마.
```

주제가 없을 때는 먼저 다음처럼 요청해도 된다.

```text
내 업무 맥락에서 해결할 만한 문제 유형을 몇 가지 보여줘.
각 후보에 주요 사용자, 반복되는 불편과 첫 번째로 검증할 행동을 함께 적어줘.
```
