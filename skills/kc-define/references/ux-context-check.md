# 사용자·업무·UX 맥락 점검표

제품 정의가 부족한지 판단할 때 사용한다. 사용자에게 UX 전문 용어를 묻지 않고 실제 업무 장면과 행동을 질문한다.

## 상태별 최소 질문

| 입력 상태 | 먼저 확인할 것 | 예시 질문 |
| --- | --- | --- |
| 아이디어 없음 | 업무, 역할, 반복되는 불편 | 어떤 업무를 담당하고, 무엇을 반복해서 확인·정리하며, 어디에서 가장 자주 막히나요? |
| 일부 맥락 | 사용자, 핵심 과업, 완료 결과 | 이 일을 가장 먼저 하는 사람은 누구이며, 화면을 열어 무엇을 하고, 어떤 결과를 보면 끝났다고 판단하나요? |
| 명확한 아이디어 | 누락된 맥락과 UX 결정 | 주 사용자와 다른 역할의 과업이 다른가요? 첫 화면에서 가장 먼저 보여야 하는 정보와 반드시 강조할 상태는 무엇인가요? |

질문은 이미 답한 내용을 반복하지 않고, 한 번에 최대 세 개까지 고른다. 답변이 없으면 질문을 계속 늘리기보다 가정과 미결정 사항으로 기록한다.

## 핵심 점검 항목

### 사용자와 환경

- 주요 사용자 역할과 보조 사용자 역할
- 사용 장소, 기기, 빈도, 긴급도와 업무 방해 정도
- 사용자가 이해하는 용어와 익숙하지 않은 용어
- 모바일·터치·키보드·저조도·접근성 제약

### 과업과 역할

- 시작 상태와 첫 행동
- 입력·검토·판단·완료 행동
- 시스템이 대신할 처리와 사람이 계속 판단할 내용
- 요청자·담당자·관리자별로 달라지는 업무와 접근 범위
- 성공, 실패, 보류와 복구를 확인하는 결과

### IA와 정보 우선순위

- 사용자가 자주 찾는 정보와 함께 비교해야 하는 정보
- 첫 화면에 둘 정보, 상세 화면으로 보낼 정보와 숨겨도 되는 정보
- 메뉴·탭·검색·필터·직접 URL 중 필요한 진입 방식
- 역할별로 같은 정보를 공유할지 별도 작업 공간을 둘지

### 사용성과 상태 가시성

- 다음 행동을 사용자가 바로 이해할 수 있는지
- 입력 오류, 빈 결과, 중복, 권한 거부와 외부 실패의 안내 방식
- 긴급·지연·위험·완료·확인 중 상태의 표현과 우선순위
- 수치·날짜·담당자·상태 중 먼저 보여야 하는 정보
- 화면 밀도, 터치 영역, 대비와 읽기 부담

## 완료 판정

다음 질문에 답할 수 있으면 제품 정의를 구현 단계로 넘길 수 있다.

- 누가 어떤 상황에서 가장 먼저 사용하는가?
- 사용자가 시작해서 완료하는 핵심 과업은 무엇인가?
- 역할이나 환경이 달라지면 IA·화면·정보 우선순위가 어떻게 달라지는가?
- 첫 화면에서 무엇을 먼저 보고 어떤 행동을 해야 하는가?
- 오류·빈 상태·위험 상태에서 무엇을 보여주고 어떻게 복구하는가?
- 무엇을 이번 버전에서 만들지 않는가?
