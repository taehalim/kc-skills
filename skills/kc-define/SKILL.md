# 제품 정의하기

사용자와 필요한 만큼만 대화하여 무엇을 왜 만들지 결정한다. 이 스킬에서는 코드를 구현하지 않는다.

## 진행

1. 제품 정의에 영향을 주는 현재 컨텍스트와 제공된 자료를 파악한다.
2. 실제 사용자, 반복되는 문제, 핵심 행동과 관찰 가능한 완료 결과를 찾는다.
3. 구현 결정을 바꾸는 정보만 질문한다.
4. 필수 범위와 제외 범위를 구분하고, 확인된 사실과 가정을 표시한다.
5. 개인정보, 회사 기밀, 저작권, 결제, 외부 연동과 공개 범위처럼 제품 방향에 영향을 주는 제약을 확인한다.
6. 플랫폼, 데이터 보관, 인증, 배포와 운영상의 제약은 기록하되 사용자가 지정하지 않은 프레임워크나 공급자를 제품 요구사항처럼 고정하지 않는다.

아이디어 예시가 필요할 때만 [예시 프로젝트](references/example-projects.md)를 보여준다. 사용자가 예시를 선택했을 때만 대응하는 샘플 PRD에서 설계 방식을 참고해 새 문서를 작성하고, 샘플의 사용자·데이터·기술·접근 정책을 그대로 승계하지 않는다.

## 산출물

- 간단하고 불확실성이 낮으면 대화 또는 사용자가 원하는 파일에 짧은 제품 정의를 남긴다.
- 여러 화면, 데이터, 권한, 외부 연동 또는 인수 조건을 구현자에게 전달해야 하면 `PRD.md`를 작성한다.
- 사용자가 PRD나 특정 형식을 요청하면 그 형식을 따른다.

상세 PRD가 필요하면 [PRD 기본 문서](assets/PRD.md)를 프로젝트의 `PRD.md`로 복사해 사용한다. 화면 상태, 데이터 규칙, 접근 범위, 외부 연동과 수용 시나리오 중 해당 제품에 필요한 항목만 남기고 구체화한다. 실제 자료 없이 예시가 필요하면 가상 데이터의 목적과 범위를 정의한다.

작성 후 미완성 자리표시자, 모호하거나 충돌하는 요구사항과 구현 전에 결정해야 할 사항이 남았는지 확인한다.

## 완료

해결할 문제, 주요 사용자, 핵심 흐름, 필수·제외 범위, 남은 가정과 생성한 문서 위치를 보고한다.
