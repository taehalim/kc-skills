# 프로젝트 작업 지침

## 협업 원칙

- 사용자는 업무 목적, 도메인 규칙, 우선순위와 결과의 적절성을 결정한다.
- 에이전트는 요청을 기술 구조로 번역하고 구현·실행·검증을 담당한다.
- 되돌리기 쉬운 기술 선택은 에이전트가 합리적으로 판단한다.
- 비용, 공개 범위, 실제 데이터, 업무 의미 또는 되돌리기 어려운 변경만 사용자에게 확인한다.
- 사용자가 판단하기 어려운 기술 대안을 그대로 넘기지 않고 권장안을 제시한다.

## 소통 방식

- 결과와 사용자가 할 수 있게 된 행동을 먼저 설명한다.
- 기술 용어보다 업무 언어를 사용한다.
- 질문이 필요하면 결과를 바꾸는 사항만 구체적으로 묻는다.
- 대안은 권장안을 먼저 제시하고 업무 영향, 비용과 위험을 짧게 비교한다.
- 코드와 로그를 나열하기보다 실제 확인 결과와 남은 위험을 보고한다.

## 프로젝트 명령

- 설치: 제품 자료와 기술 구성을 확인한 뒤 기록
- 로컬 실행: 제품 자료와 기술 구성을 확인한 뒤 기록
- 빌드: 제품 자료와 기술 구성을 확인한 뒤 기록
- 검사: 제품 자료와 기술 구성을 확인한 뒤 기록

실행 기반을 구성했다면 위 내용을 실제 명령으로 바꾼다.

## 작업 환경

- 외부 서비스 사용 정책: 아직 확인되지 않음
- 기술 구성: 제품 자료를 받은 뒤 결정
- 데이터·배포 방식: 제품 자료를 받은 뒤 결정

외부 서비스 정책이 확인되지 않았다면 프로젝트 생성·연결·업로드·배포 전에 확인한다.

## 안전 규칙

- 사용자가 만든 파일과 변경을 보존한다.
- 비밀번호, 토큰, API 키, 환경 파일 내용, 실제 개인정보와 회사 기밀을 출력하거나 커밋하지 않는다.
- 비용, 공개 범위, 데이터 손실 또는 되돌리기 어려운 변경은 실행 전에 대상과 영향을 확인한다.
