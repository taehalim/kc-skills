# 안전하게 복구하기

Git을 내부 안전장치로 사용하고 결과는 사용자가 이해할 수 있는 상태와 행동으로 설명한다. 복구는 변경 손실 위험이 있으므로 다른 스킬보다 보수적으로 진행한다.

## 진행

### 상태와 대상 확인

1. 현재 브랜치, 변경 파일, 최근 기록과 보존된 변경을 Git에서 직접 확인한다.
2. 사용자가 원하는 화면이나 동작 상태를 기준으로 복구 대상을 특정한다. commit hash나 Git 방식을 고르게 하지 않는다.
3. 관련 없는 변경이 섞였는지, 안전하게 분리할 수 있는지 확인한다. 같은 파일의 같은 부분에 섞여 있으면 자동 복구하지 않는다.
4. 데이터베이스, 파일 저장소, 환경변수, 배포 설정과 외부 서비스 상태가 함께 바뀌었는지 확인하고 Git으로 복구되지 않는 항목을 구분한다.

### 되돌리기

1. 현재 작업이 사라지지 않도록 먼저 보존하고 보존 위치를 기록한다. 비밀 파일이나 ignored 파일을 강제로 추적하지 않는다.
2. 미커밋 변경은 대상 범위를 안전하게 보존한 뒤 요청한 변경만 되돌린다.
3. 기록된 변경은 이력을 지우지 않는 복구 방식을 사용한다. `reset --hard`, 강제 checkout, 광범위한 삭제와 history rewrite는 사용하지 않는다.
4. 복구 후 사용자가 원한 동작과 영향을 받을 기존 핵심 동작을 확인한다.
5. 복구되지 않은 외부 상태와 다시 적용할 수 있는 지점을 보고한다.

### 다시 적용하기

1. 직전 복구 기록과 현재 변경을 확인하고 충돌 가능성이 있으면 현재 작업을 먼저 보존한다.
2. 기록된 stash 또는 복구 commit을 이용해 변경을 다시 적용한다. 기억이나 추측으로 코드를 재작성하지 않는다.
3. 재적용된 동작을 확인하기 전에는 보존 기록을 삭제하지 않는다.

안전한 기준점이나 복구 기록이 없으면 임의로 정상 상태를 추측하거나 재작성하지 않는다.

## 완료

복구한 상태, 보존한 현재 작업, 실제 확인 결과, Git으로 복구되지 않은 외부 상태와 다시 적용할 수 있는 지점을 보고한다.
