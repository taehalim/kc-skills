# 사용자 흐름 단위 구현 규칙

기능을 파일 종류가 아니라 사용자의 완료 행동으로 나눈다. 이는 에이전트가 구현 순서와 검증 지점을 정하기 위한 내부 기준이며, 사용자가 언제나 기능 하나씩 요청해야 한다는 규칙이 아니다.

| 좋은 단위 | 나쁜 단위 |
| --- | --- |
| 참가 신청을 입력하고 저장 결과를 확인한다 | 폼 컴포넌트를 만든다 |
| 저장된 예약을 운영 화면에서 조회한다 | 데이터베이스 코드를 작성한다 |
| 견적 두 개를 입력하고 누락 품목을 확인한다 | 프런트엔드와 백엔드를 만든다 |

필요할 때 나누는 각 단위는 다음을 모두 포함한다.

1. 사용자가 시작할 수 있는 화면 상태
2. 필요한 입력과 검증
3. 데이터 또는 계산 효과
4. 성공·빈 상태·핵심 오류 중 관련 상태
5. 실제 행동을 통한 확인

데이터나 외부 연동이 필요한 흐름은 화면과 분리해 마지막에 몰아넣지 않는다. 공개 환경 검증은 사용자가 배포를 요청했고 완료 조건에 포함될 때 진행한다. 요구사항이 명확하고 위험이 낮은 연속 변경은 여러 단위를 구현한 뒤 함께 확인할 수 있다.
