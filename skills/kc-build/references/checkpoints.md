# 체크포인트 품질 기준

좋은 체크포인트는 다음 조건을 모두 충족한다. 체크포인트는 모든 작은 변경마다 만드는 것이 아니라, 이름 붙일 수 있는 정상 상태가 생겼거나 위험한 변경에 들어가기 전에 만든다.

- 앱이 정상적으로 실행되거나 빌드된다.
- 이름 붙일 수 있는 사용자 행동 하나가 시작부터 관찰 가능한 결과까지 동작한다.
- 변경 파일이 해당 행동 구현에 속한다.
- 비밀값과 서비스 제공자 캐시가 포함되지 않는다.
- 설명은 바뀐 파일이 아니라 사용자가 할 수 있게 된 일을 말한다.

예시:

- 좋음: `이벤트 기본 화면을 공개 URL에서 확인 가능`
- 좋음: `참가 신청을 저장하고 운영 화면에서 조회 가능`
- 나쁨: `update files`
- 나쁨: `WIP backend and styles`

저장소에 기존 체크포인트 규칙이 있으면 그 규칙을 우선한다.
